広聴AI / keyword-curation ワークフロー

概要

このディレクトリは、CSV 形式のコメントデータを広聴AIのレポート生成パイプラインにかけた中間出力を起点に、keyword-curation で人手確認した entity linking 結果を使って、情報公開請求を行なった第7次エネルギー基本計画（令和7年2月）のパブリックコメントに出てくるエンティティとその関係を整理するための作業用ワークフローです。

これまで、私（人間文化研究機構 亀田尭宙）は、千葉大学の石井康平氏と共に環境政策形成に関する審議会の議事録分析に基づく主題構成比較などで、広聴AIと類似したBERTopicを用いた政策形成過程の分析を、議事録、パブコメ、政策文書などの資料について環境政策を対象に行なってきました。

この幅を広げるにあたって、エネルギー政策の政策形成過程に着目した時に、以下のような話題がありました。

  • エネ基パブコメに４．１万件超　過去最多　原発へ「懸念の声」、計画に反映：朝日新聞
  • エネルギー基本計画のパブリックコメントでAI利用、4000件弱投稿か - 日本経済新聞

そこで、公開されているパブリックコメントと別途、情報公開請求で元データを入手し、大量の類似したコメントから、有意義なエンティティとその関係を抽出することを目標にしました。また、広聴AIのような既存のツールを使ったワークフローにすることで、実務家のワークフローに組み込める形を目指しました。

成果物は 議論ビューアー で、エンティティ間のネットワークやコメントに基づくエンティティ単位・ペア単位の意見要約をブラウズできるようになっています。数が少ないが重要な意見を拾い上げることができているという点で一定の価値があるワークフローを構築できたのではないかと思っています。

今後、学術的な検証や、評価、このワークフローを実務化や他の研究者が容易に利用できるようにするための工夫などに取り組んでいきたいと考えています。

入力データ

上流の入力は、コメント CSV を広聴AIのレポート生成パイプラインで処理した中間ファイルです。 このワークフローでは、広聴AIで生成した次のファイルをこのリポジトリの data/ に配置してから各スクリプトを実行します。

  • data/hierarchical_result.json: 階層クラスタリング結果。L2 クラスタラベルの入力として使います。
  • data/hierarchical_clusters.csv: argument と L1/L2 クラスタ ID の対応。コメント索引作成と局所クラスタの並び合わせに使います。
  • data/final_result_with_comments.csv: argument、コメント ID、元コメント本文。コメント索引とローカル本文参照ファイルの作成に使います。
  • data/embeddings.pkl: argument embedding。argument の局所クラスタ作成に使います。

ここでいう L2 クラスタラベル は、広聴AIがコメントから抽出した argument を 階層クラスタリングしたときの第 2 階層クラスタにつけられた代表ラベルです。 個別コメント本文ではなく、複数の argument をまとめた論点カテゴリの短い説明として扱います。

このリポジトリでは、元コメント本文を含む data/comment_texts.json はGit 管理から除外しています。一方、要約、一部引用した元コメントはデータに含まれています。

ワークフロー

0. CSV を広聴AIで処理する

最初に、元のコメント CSV を広聴AIのレポート生成パイプラインに入力します。 この工程で、コメント本文から argument が抽出され、argument embedding が作られ、 argument の階層クラスタリングとクラスタラベル生成が行われます。

このリポジトリのスクリプトは、広聴AIの処理そのものは実行せず、 data/ に配置された広聴AIの中間ファイルを読みます。 広聴AIをリポジトリ直下で実行した場合、中間ファイルは通常 apps/api/broadlistening/pipeline/outputs/ 以下の実行 ID ごとのディレクトリに出力されます。 必要なファイルの場所は、次のように探せます。

find /path/to/kouchou-ai/apps/api/broadlistening/pipeline/outputs \
  -name hierarchical_result.json \
  -o -name hierarchical_clusters.csv \
  -o -name final_result_with_comments.csv \
  -o -name embeddings.pkl

対象の実行 ID のディレクトリを確認したら、必要な中間ファイルをこのリポジトリの data/ にコピーします。

cp /path/to/kouchou-ai/apps/api/broadlistening/pipeline/outputs/<run-id>/hierarchical_result.json data/
cp /path/to/kouchou-ai/apps/api/broadlistening/pipeline/outputs/<run-id>/hierarchical_clusters.csv data/
cp /path/to/kouchou-ai/apps/api/broadlistening/pipeline/outputs/<run-id>/final_result_with_comments.csv data/
cp /path/to/kouchou-ai/apps/api/broadlistening/pipeline/outputs/<run-id>/embeddings.pkl data/
  • data/hierarchical_result.json は、L2 クラスタラベルを取り出して entity linking 候補生成に使います。
  • data/hierarchical_clusters.csv は、各 argument がどの L1/L2 クラスタに属するかを引くために使います。
  • data/final_result_with_comments.csv は、argument と元コメント本文、コメント ID を対応付けるために使います。
  • data/embeddings.pkl は、argument をより細かい局所クラスタに分けるために使います。

1. Entity linking 候補を作る

scripts/prepare_entity_candidates_no_draft.py は、data/hierarchical_result.json の L2 クラスタラベルから Wikidata にリンクできそうな語句を LLM で抽出し、Wikidata Search API の候補から 最も適切な QID を選びます。

出力は data/data.json です。この時点の結果は自動生成なので、 keyword-curation で entity ID、ラベル、説明、リンク要否を人手確認します。

python scripts/prepare_entity_candidates_no_draft.py

2. Entity 説明を整える

scripts/refine_entity_descriptions.py は、キュレーション済み data/data.json の entity description を日本語で短く整えます。

これは後続のグラフ表示や LLM による意見抽出で、エンティティの意味を安定させるための工程です。

python scripts/refine_entity_descriptions.py --only-weak

3. Argument の局所クラスタを作る

scripts/build_argument_microclusters.py は、argument embedding に Ward 法を適用し、 近い argument を局所クラスタにまとめます。ここでいう局所クラスタは、全体の階層クラスタとは別に、意味的に近い argument をさらに細かくまとめた小クラスタです。広聴AIの argument はコメントごとに抽出されるため、コメントが似ていた場合、意味的に重複した argument が多数抽出されます。今回扱ったパブコメデータは特にその点が問題になったためこのプロセスを挟んでいます。

入力は data/embeddings.pkl と data/hierarchical_clusters.csv です。 出力は data/argument_microclusters_t0.7.csv です。各局所クラスタにはセントロイド argument が付き、 後続工程で代表的な論点を取り出しやすくします。

python scripts/build_argument_microclusters.py --threshold 0.7

4. コメントとクラスタの索引を作る

scripts/build_cluster_comment_index.py は、argument、コメント ID、階層クラスタ、 局所クラスタの対応をまとめます。

入力は data/final_result_with_comments.csv、data/hierarchical_clusters.csv、 data/argument_microclusters_t0.7.csv です。 出力は次の 2 つです。

  • data/cluster_comment_index.csv: 公開・分析用の索引
  • data/comment_texts.json: コメント本文のローカル参照用ファイル
python scripts/build_cluster_comment_index.py

5. Wikidata property path を探索する

scripts/discover_property_paths.py は、同じ L2 ラベル内で共起した QID ペアについて、 Wikidata の P31、P279、P361、P527 などを調べ、直接関係や共通上位クラスを探します。

出力は次の 2 つです。

  • data/property_paths.tsv: 発見した関係
  • data/entity_props_cache.json: Wikidata API 結果のキャッシュ
python scripts/discover_property_paths.py

6. Entity graph を作る

scripts/build_entity_graph.py は、data/data.json と data/property_paths.tsv から エンティティ中心のグラフを作ります。

グラフには 2 種類のエッジがあります。

  • co_mention: 同一 L2 ラベル内での共起
  • wikidata_property: Wikidata property による関係

出力は data/entity_graph.json です。

python scripts/build_entity_graph.py

7. Entity ごとの意見を抽出する

scripts/extract_entity_opinions.py は、各エンティティが登場するクラスタに対応するコメントを集め、 そのエンティティへの立場、主要な意見、他エンティティとの関係候補を LLM で抽出します。

入力には data/comment_texts.json が必要です。出力は data/entity_opinions.json です。

python scripts/extract_entity_opinions.py --resume

8. ペア関係を抽出する

scripts/extract_pair_relations.py は、data/entity_opinions.json と data/entity_graph.json を使ってスコアの高いエンティティペアを選び、 両者が共起するコメントからペア単位の関係説明を LLM で作ります。

出力は data/pair_relations.json です。

python scripts/extract_pair_relations.py --resume

9. 議論ビューアーを生成する

scripts/build_pair_relation_viewer.py は、data/pair_relations.json と data/entity_opinions.json をブラウザで読むための静的 HTML を生成します。

出力は pair_relation_viewer.html です。

python scripts/build_pair_relation_viewer.py

LLM を呼ぶ工程では OPENAI_API_KEY が必要です。
